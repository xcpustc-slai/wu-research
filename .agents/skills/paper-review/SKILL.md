# 论文阅读与复现评估

服务于人形机器人研究：理解技术方法，筛选能支持仿真、修改和真机实验的基础。遵循项目 AGENTS.md 的读取、写回与同步规则；结合 BLUEPRINT.md 和 papers.md 已有讨论继续工作。回答与归档语言紧凑，分析可以充分，记录只保留核心结论及必要依据。

## 阅读与核验

- 核查原文版本、阅读日期与实际阅读范围；关键问题正文未交代时，继续查官方补充材料、代码与所引用方法。引用方法的训练细节不能直接当作本文的实现事实。
- 基本信息核实首次上传日期、所读版本、共同一作、通讯、单位及录用情况。单位对应所读版本；录用优先查官方会议或出版页面。未核实不写成“未录用”，论文未提供的信息不猜测。
- 区分作者主张、原文／代码已核实事实和我们的推断。影响判断的实验结论核对实验条件、对照和适用范围；证据链接及章节、图表、代码位置就近附在相应结论中。

## 系统拆解与训练说明

- 先交代整体输入、输出、模块调用关系，以及高层决策如何落到执行器。按原文名称与层级拆分一级组件、子模块、agent 和底层算法；功能概括放在处理流程中，不冒充正式模块名。
- 系统表可以将子模块分行，但第一列必须标明父子路径，不能把不同层级当作并列组件。行数按论文实际结构增减，不照搬某篇论文的模块数量或名称。
- 训练表沿用系统表的结构名称、顺序和粒度，逐项说明训练、复用与数据，再写作者在本文中的设计；不要另按“抓取／导航”等功能重新分组而失去对应关系。
- 对学习模块说明：本文是否训练、从头初始化还是基于哪个模型／checkpoint 微调、哪些参数冻结、哪些部分直接复用。只写有依据的型号和训练方式；未报告微调不等于已核实冻结，已有 RL 策略也不等于本文作者亲自重训。
- 数据说明跟随对应模块：是否需要训练数据、名称或来源、采集／生成方式和用途；已披露且影响判断时补充规模。区分离线数据集、遥操作示范、在线仿真 RL 经验、推理输入和逐实例优化；单独识别对照基线使用的数据，不能归到作者方法上。
- 作者称 training-free 时，说明适用范围，不能据此否认复用模型的预训练经历。几何规划、规则与优化过程不能默认称为训练；作者新增设计也可能是模块组合、接口或控制流程。

## 开源核验与状态

检查官方主页、仓库及资源实际内容：系统代码与环境／资产、权重与加载方式、数据或生成路径、训练配置与入口、仿真推理和真机部署入口。不要凭“Code”按钮、演示视频或开源承诺判定可复现。必要时检查版本，但不把仓库树、commit 列表和完整核查过程搬入论文条目。

归档从下列状态选择一项，紧跟最新检查日期 `[YYYY-MM-DD]`：

- **完全没开**：未公开本文系统实现；只有论文、网页或演示也属此类，注明判断范围。
- **缺少关键组件**：已公开部分实现，但缺少目标系统运行所需的代码、权重、资产等关键材料。
- **可以sim**：已核实提供仿真运行所需材料与入口；若仅支持预训练推理、缺训练材料，在括号简记。
- **sim+deployment**：除仿真材料外，还提供真机部署代码与说明；注明关键硬件适配条件。

状态描述材料可用程度，实际运行状态另在同一行注明“未运行／已仿真验证／已真机验证”等。只读文件不能写成已跑通，发布部署代码也不代表已在我们的硬件验证。信息不足时写“未核实[日期]”及原因，不强行归类。默认只归档状态、决定分类的缺口或条件、实际运行状态和必要的官方代码链接；详细复现评估按用户问题展开。

## 写入 papers.md

每篇论文维护一个稳定条目，按以下顺序组织：重点关注、开源情况、基本信息、核心问题、系统拆解、训练／复用／新增、关键 Q&A。前四项名称和顺序固定，不合并；重点关注填写 True 或 False，保留用户已有标记，不默认所有论文都为 True。没有实质问答时省略 Q&A。

```markdown
## 论文简称 — 完整标题

**重点关注**：{True 或 False}

**开源情况**：{状态}[YYYY-MM-DD]（关键缺口／条件；实际运行状态；必要的官方代码链接）。

**基本信息**：阅读日期 YYYY-MM-DD；arxiv上传：YYYY-MM-DD（所读版本及日期，必要时注明阅读范围／补充材料）；一作（共同）：姓名；通讯：姓名；单位：单位；是否中稿：是／否／未核实，会议或期刊及年份；[项目主页](URL)，[arxiv](URL)。

**核心问题**：一句话概括作者要解决的问题与方法思路。

**系统拆解**：依据原文说明整体输入输出、一级组件及调用关系，附必要章节／图号链接。

| 一级组件／子模块 | 原文内部结构 | 输入 → 处理 → 输出 |
|---|---|---|
| {原文一级组件名} | 内部模块／agent／算法 | 输入 → 处理 → 输出 |
| {原文一级组件名 → 子模块名} | 内部模块／agent／算法 | 输入 → 处理 → 输出 |

**训练、复用与新增**：与上表逐项对应，必要时注明整体训练声明及其适用范围。

| 对应结构 | 训练、复用与数据 | 作者在本文中的设计 |
|---|---|---|
| {与系统表同名} | 训练方式、基础模型／权重、冻结／复用状态；数据来源与用途；未披露项及必要证据 | 本文新增方法或组合设计 |
| {与系统表同名} | 同上，按该模块实际情况填写 | 本文新增方法或组合设计 |

**关键 Q&A（YYYY-MM-DD）**：Q：已讨论的重要问题。A：简要答案、依据和必要修正。
```

模板中的占位项按核实内容替换；没有 arXiv 或项目主页时注明未提供并使用可用的正式原文链接。来源支持不足的字段标为未披露／未核实，不为填满格式推断事实。

不再设置独立的“入口与版本”“核心理解”“证据与限制”“开源与复现／复现可行性”“与课题关系”章节。开源结论集中在顶部状态行；必要的证据、限制及与课题相关的判断就地融入对应字段或 Q&A，用户明确要求展开时再补充。避免在 Q&A 重复整张表，合并重复问题；版本更新与关键修正写回原条目，跨论文共识按项目规则归入 BLUEPRINT.md。
